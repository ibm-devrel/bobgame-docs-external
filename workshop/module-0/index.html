Introduction

Deep Blue Drive Heist is a game made for players to experience the world of agents and learn how to use AI coding assistants, like IBM Bob, to improve an agent. In this workshop, you will be using Deep Blue Drive Heist to understand:

  • What agents are and how to use an agent
  • How to build and improve an agent for simple problem-solving
  • How to apply agentic techniques to complicated, real-world problems
  • How to build an experimental framework for your agents

The Game World

Deep Blue Drive Heist is a text adventure game with a simple premise: a notorious supervillain called “The Architect” has stolen an important drive that holds a crucial piece of IBM history. The drive is called “Deep Blue”, in reference to the chess supercomputer IBM developed that beat Russian chess grandmaster Garry Kasparov in two historic six-game chess matches in 1997.

Your agent's task is to chase The Architect across multiple cities, talk to NPCs, find leads hidden in IBM's databases, and recover the drive as fast as possible.

You do not play this game, nor do you control the agent that does. Instead, your task is to improve the agent with the help of IBM Bob, your AI coding assistant.

One note before we start: we'll use the word "agent" for two different things in this workshop:

a) Bob, the coding agent we'll use to update the game code; and
b) the PlayerAgent, called the Investigator in the game, which we develop and change using Bob.

Why This Game?

This game world is designed to help players of all development experience levels understand how to build and improve an agent. The game's map is a place where agents both struggle with and solve complex problems, applying problem-solving strategies as they search for the drive across cities and NPCs.

This kind of problem-solving mirrors many real-world problems, where an agent must navigate layers of information, find and keep track of answers, and stay aware of its end goal while focusing on the job at hand.

What Is an AI Coding Agent and How Do We Use One?

AI coding agents are software tools that help developers generate, debug, and analyze code. Examples include IBM Bob, Claude, and Cursor.

You can use an AI coding agent to analyze problems and implement solutions in your codebase without losing track of your progress. Good prompts give the agent context: what the core problem is, and what information it has to work with.

How IBM Bob Works

Bob works directly in your repository, where it can inspect, navigate, and modify your files and their history. It can also run commands, test suites, and build scripts, and analyze the output right in the chat.

By default, Bob asks for your approval before it reads, writes, or executes anything (see Bob Permissions below). Bob also saves checkpoints as it works: a safety net that tracks state automatically, lets you review diffs, and lets you roll back any change you're not happy with.

Prompting and Rules

When you send Bob a prompt, it gathers the context it needs to decide which tools to use. That includes its mode instructions, any project rules the developer has set, and other relevant context from the workspace.

AGENTS.md is a Markdown file, usually in the repository root, that acts as a persistent instruction manual for Bob. It may include specific rules that Bob must follow before executing any changes, such as style guidelines, files to ignore or target, and specific strategies it should follow.

For this repository, we've designed the AGENTS.md file specifically to support players of this game. It keeps Bob focused on changing player_agent.py, explains the goal of the game, and offers some ideas about strategy. Take a look at AGENTS.md now to see the text-based guardrails that are in place.

Bob Modes

By switching between Bob's modes (Ask, Plan, Agent), you can keep Bob focused on the problem at hand and have it break down the problem and solution at your own pace.

Each mode comes with base instructions that tell Bob which tools to use and what goal to center its responses on.

There are three predefined modes:

Mode Use Case Most Useful For...
Ask For questions about the project documentation, the codebase, or anything else technical Clarifying and understanding concepts and breaking down the code without having to change anything
Plan For creating a deliberate project plan and strategizing changes before they are applied Breaking down complex problems and using Bob to develop a strategy, brainstorm solutions, and explore parts that need more explanation
Agent For writing and refactoring code in the codebase Supporting your application of changes to the agent, whether that be adding new files and functions, changing parts of the code, or fixing bugs

You'll probably use Agent mode most often during Deep Blue Drive Heist. You can also add custom modes in the Modes tab of Bob's settings.

Bob Permissions

Bob's permission settings let you give it more autonomy. For this workshop, since the code isn't sensitive (and especially if you're using a computer set aside for this lab), we recommend giving Bob full permissions so fewer permission prompts slow you down.

If you'd rather approve each action yourself, leave them unchecked.

Your Activity

Exercise · Try the game

Try out Deep Blue Drive Heist once, using the player guide and the in-game tutorial mode as your references. Use Bob to improve your agent, and then press the green New Game button to observe your changes.

If you're not sure what changed, ask Bob to compare the logs from your games and point out any improvements. This helps you see what your agent did differently and decide what to change next.

In general, it's good practice to ask Bob to summarize its work, so that you stay aware of the changes as development goes on.

Tip

This is part of a practice called spec-driven development, where developers keep track of what they're building with AI by writing, and checking against, detailed specs for what the AI should build.

Here's an example prompt to get started:

Bob · Agent modeHi Bob, look at the logs that are updating as the agent plays the game. Could you outline what issues the agent may be having with completing the game faster, and make changes to the player agent file based on what you find?

You'll find more prompts in the player guide's quick reference.

At the end of this exercise, you should have:

  • Run the game with the default player agent at least once
  • Used Bob to make one change to your agent
  • Run the game a second time with the new player agent
