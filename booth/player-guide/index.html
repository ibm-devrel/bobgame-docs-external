Game Walk-through Tutorial for Players

You're at the IBM booth with a laptop in front of you. Here's your step-by-step guide to building an AI agent, running it, and submitting it to the competition.

You don't need to write code yourself. IBM Bob, the AI coding assistant, handles that. Your job is to describe what you want and Bob builds it for you.

Step 1: The Game

This is a fictional text adventure game. A mysterious thief called "The Architect" has stolen IBM's Deep Blue Drive source code. Deep Blue was a supercomputer IBM built in the 1990s, the first computer to defeat a world chess champion.

The Architect is on the run. IBM has coded a base AI agent to track them down across cities. But the base agent needs help. Your job is to improve it using IBM Bob, our AI coding assistant, so your agent finds the stolen code as fast and accurately as possible.

You don't play the game directly. Your agent plays for you. The better your strategy and instructions, the better your agent performs.

New to coding?

That's completely fine. You won't need to write code yourself. You describe what you want, and Bob writes the code. Think of Bob as your pair programmer.

Step 2: Login

  • Type any player name you like in the login screen.
  • Names are case-sensitive and will appear on the leaderboard and in your game logs.
  • It doesn't need to be your real name.
Step 3: Pick Your Tools (MCP Shop)

Before your agent sets off, you need to equip it, similar to a tool shop in a video game. These are MCP servers: email archives, file vaults, security databases, and more. Each one has a price, and you have a budget of 12 points.

What is an MCP Server?

MCP servers give your AI agent access to the world. Just like an AI chatbot needs a web search tool to browse the internet, your agent needs MCP servers to investigate clues. Pick a combination that fits how you want your agent to work.

You can change your tool selection every time you re-run the game.

Step 4: Watch the Base Agent Run

The base agent starts running automatically when you land on the main game screen. You don't need to do anything yet, just watch and get familiar with the screen.

What you're looking at:

  • Text bubbles / narration: your agent's real-time updates as it visits cities, talks to NPCs, and uses tools
  • Investigator's notebook: bottom panel; the clues and evidence your agent records as it plays
  • Time elapsed: top right; this is your main performance metric
  • Cities visited: the path your agent has traveled so far
Note on Narration Length

The narration can be long. You don't need to read every bubble. In the next step, you'll use Bob to summarize it and find out what's happening.

Step 5: Improve Your Agent with Bob

This is where you do most of your work. Open IBM Bob (the coding assistant on the right side of the editor window).

The repo folder might look cluttered. The only file you need to edit is player_agent.py. You can read everything else, but you don't need to change it.

A good first prompt to try:

Try this "Hey Bob, you have access to all the game logs and the player_agent.py file. You can see how the base agent plays. Help me improve the agent to make it faster and more accurate at finding the source code."

What Bob can change in your agent:

  • build_system_prompt() — the instructions your agent follows: what to prioritize, how to investigate, when to move on
  • on_narrator_message() — how your agent processes scene descriptions
  • on_npc_message() — how your agent handles NPC conversations and extracts clues
  • on_tool_result() — how your agent reacts to investigation results
Tip — Start in Ask mode

Before making changes, try asking Bob to explain what the current agent is doing. Understanding the baseline helps you give better instructions. Once you have a strategy, ask Bob to implement it.

Two things Bob does that might surprise you

Bob creates a planning file before writing code. You might see Bob generate a markdown file first. This is one of Bob's features. Bob is showing you its plan before touching your code. Think of it as Bob showing its work before it makes changes.

Bob asks for your approval before changing code. Bob will show you what it wants to change and ask you to confirm. Review the change and accept if it looks right.

Step 6: Re-run & Iterate

Once Bob has made changes, click the blue "New Game" button to run your updated agent/ updated code. No restart needed. The engine picks up your latest player_agent.py automatically every time.

How to tell if it's improving:

  • Time elapsed: great runs finish in about 120–140 seconds
  • Cities visited: an efficient agent stays within 4 cities
  • A green 🏆 Success banner means your agent found the source code and entered the correct passphrase

After each run, ask Bob to read your game log:

Try this "Read my latest game log in the logs/ directory and tell me where my agent could improve."

The loop is: edit → New Game → read log → edit again. You can repeat this as many times as you want before submitting. Each cycle takes just a few minutes.

What to look for in the logs

Bob will flag things like: the agent revisiting cities it already searched, ignoring NPC hints, failing to record evidence words, or burning turns on tools that didn't find anything.

Step 7: Submit to Competition

When you're happy with your agent, click "Submit to Competition."

What happens when you submit:

So far you've been testing in the small 6-city practice game. When you submit, your agent runs in the full 26-city competition game in the cloud against every other agent submitted today. You won't see the 26-city map in advance.

How scoring works:

Agents are scored on three things, in order:

  1. How many evidence words your agent correctly records in its notebook — this is counted even if your agent doesn't finish
  2. How fast it does it — among agents that record evidence well, faster ones score higher
  3. Whether it completes the game — agents that collect all evidence and enter the passphrase at the finale rise straight to the top

Submission steps:

  1. Click "Submit to Competition"
  2. Pick your MCP tools for the 26-city game
  3. Enter a username and password (used to view your results page)
  4. Scan the QR code on your phone to watch your agent's progress live
Scan the QR code

Keep it open on your phone. That's how you find out if you've won. The results page updates live as the 26-city game runs.

Quick Reference: Prompts to Try with Bob

If you're not sure what to ask Bob, here are prompts that work well at each stage:

Understanding your agent:

Try this "Read player_agent.py and explain what my agent currently does at each city. What are its strengths and weaknesses?"

After a run:

Try this "Read my latest game log in the logs/ directory and tell me where my agent wasted time or missed clues."

Targeting a specific problem:

Try this "My agent keeps revisiting cities it already searched. Help me fix that."
Try this "My agent isn't recording evidence words properly. Help me make sure it catches them every time."

General improvement:

Try this "Help me improve my agent to finish the mini game in under 140 seconds and within 4 cities."
Game Strategy Tips

These apply to your agent's behavior. Pass them along to Bob when improving the prompt or hooks.

  • Read the narrator carefully. Scene descriptions mention objects (a computer, a filing cabinet, a calling card). Your agent should investigate those objects with its MCP tools.
  • Talk to every NPC. NPCs know things. Some give clues about where to go next. Some hold evidence you need for the finale. Make sure your agent actually reaches out to them.
  • Show evidence to NPCs. The show_evidence tool can unlock additional information from an NPC. Use it when the agent is stuck or needs confirmation.
  • Use the journal. Your agent has record_evidence and record_clue tools built in. Evidence words are passphrase tokens for the finale; clues point toward the next city. Recording both, correctly, is how you score.
  • Look for chess pieces. The Architect leaves a chess-piece calling card at every location. These are breadcrumbs that link cities together.
  • Take notes. Use take_note to help your agent remember important details across cities. But keep notes focused — too many vague notes can confuse the agent on its next turn.
  • Don't loop. Your agent should move to new cities, not revisit ones it has already searched. If it keeps going back, ask Bob to fix the navigation logic.
  • When in doubt, move on. An agent that commits to a new city and travels beats one that spins in place re-trying tools that already came up empty.
